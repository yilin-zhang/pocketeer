Keys mean the same thing on every tab. Lowercase acts on the selected row,
uppercase on all of them. Keys are tinted by kind: sage brings something
into the library, slate writes to the card, mauve renames or changes
covers, rose removes.

Global
  Tab / Shift-Tab, 1-5   switch tabs (Games, Memories, Cores, BIOS, Card)
  j/k, arrows, PgUp/PgDn  move; Emacs keys too: C-n / C-p, C-v / M-v, C-f / C-b, C-g cancels
  /                        type to filter the list (Enter/Esc to stop typing; Esc again clears it)
  text fields              Emacs editing: C-a / C-e, C-b / C-f, M-b / M-f, C-d, M-d, C-w,
                           M-Backspace, C-k, C-u, C-y
  l                        cycle what the list shows (or click a segment in the filter bar)
  r                        reload everything (card, inventory, library)
  ?                        this help
  q, Ctrl-C                quit
  mouse                    click tabs, rows, filter segments and buttons; wheel scrolls;
                           drag the border between two panes to resize them

Cores   (installed cores and the whole inventory in one list)
  u               install the selected core, or update it to the latest release (also Enter)
  U               update every installed core that has an update
  x               remove the selected core (Cores/, Presets/, Settings/ are deleted)

BIOS   (every file the installed cores declare, with its status)
  p   move files you dropped at the SD card root into the folders cores expect

Games   (the library and the card in one list; WHERE says which)
  n     create the library (when there is none yet)
  a     import ROMs from this computer: a folder, a ROM or a zip; each file's platform
        comes from its extension (asked only when none says)
  i/I   import the selected card-only ROM / every card-only ROM into the library
  e     choose local/AP rename, or adopt the other copy's name; preview first
  d     check cached/automatic DATs again; retry failed identification
  t     rename games to the standard (No-Intro) names they match; imports offer this too
  x     library game → .trash/ inside the library;  card-only ROM → deleted from the card
  f     download the cover from libretro-thumbnails (missing covers are also
        downloaded on start and after imports)
  c     use a PNG/JPEG/WebP image from this computer as the cover (confirm
        before replacing)
  s     copy the selected local game to the card
  b     back up the selected game's saves
  B     back up every save on AP; conflicts offer AP / computer / leave unchanged
  Enter / →   the selected game's saves: each save, its copy on AP, the library's
              backup and older versions. SAVE column: ✓ backed up (n older
              versions), ← AP is newer, ! changed on both sides, · library only
    b / B   back up this game's saves / every save on AP
    p       put the selected backup or older version on AP (AP's copy is archived)
    x       trash the selected copy: AP → deleted after archiving; library → .trash/;
            on the file name → the backup and every older version
    Esc     back to the list

Memories   (save states made from the Pocket's menu, on the card and in the library)
  b   back up the selected Memory
  B   back up every new or changed Memory
  p   put the library's copy back on AP
  x   trash it: from AP (archived first) or the library's copy (asks when both exist)
  A Memory holds the whole machine, the game's save included, and loads only in
  the core that made it; a newer core version may not load it.

Card
  x   scan for macOS junk in the background, then preview removal
      (._* files, .DS_Store, __MACOSX); never scanned on startup

Every file change shows its plan first with Apply / Cancel buttons: click one, or
y / Enter applies, n / Esc cancels, ←/→ moves the focus. In checklists Space
toggles one item and a toggles all; in path prompts matching entries are listed
as you type: ↓ picks one, Tab completes, Enter takes the pick (or submits when
nothing is picked).

No SD card? The Games tab still manages the library; Cores, BIOS and Card
wait for one. A card that is plugged in (or pulled) is noticed without pressing
r, and the screen reloads by itself when the card or the library changes
outside pocketeer. The library is the backup: what pocketeer removes from the
card is deleted.

ROM identity checks run in the background. New files need a full read; cached
files use small samples. WHERE uses ? while identity is unresolved. A local
ROM keeps its local filename as the title; ≠ means an AP copy has another name.
Details show each exact AP path and verification confidence. No automatic rename
is queued. `pocketeer card check --full` explicitly reads every ROM byte.

DAT identification runs in the background at startup and after ROM imports.
? = not checked, ✓ = matched, – = no match, ! = retryable failure,
~ = multiple matches, n/a = no automatic DAT source. Details show the standard
name and any retry error. Local filenames stay unchanged; t previews renames.
DATs are cached for seven days. Changed catalogs trigger another lookup;
network failures are retried on the next launch or with d. Offline mode uses
cached DATs. No match means absent from that catalog, not a damaged ROM.
